# Checkpoint 70 — Named history refs, attached checkout and portable labels

Date: 2026-10-13
Branch: `refactor/riverpod-architecture`
Starting verified baseline: Checkpoint 69 R3, clean analyzer, 272 passing tests.

## Implementation

- `HistoryRefRepository` now supports **lightweight** named branch and
  bookmark creation at an existing checkpoint (no duplicated subtitle state),
  rename, delete and branch-target lookup.
- New references are checked for name format, namespace/kind, path traversal,
  naming collisions/prefix conflicts, owning session and valid checkpoint.
  Names cannot be duplicated or attach to foreign checkpoints.
- Rename updates symbolic HEAD in the same Isar transaction when the active
  branch is renamed. Deletion refuses HEAD, main and currently attached branch.
  Manual refs can be explicitly deleted (unpinning their checkpoint).
- `CheckpointRepository` exposes these operations through the shared
  CheckpointManager for future mobile/desktop history interfaces.
- **Checkout by checkpoint now detaches HEAD**. It preserves main/feature
  branch tips. Named `checkoutBranch` restores the exact checkpoint through
  the existing history reconstructor and transactionally attaches HEAD to
  the target branch only if its tip remains unchanged. Normal V2 mutations
  then advance only the attached branch; detached mutations advance HEAD.
- Branch attachment and HEAD checking operate in the same write transaction
  as restoring the subtitle working tree and active checkpoint marker.

## Portable project compatibility

- `.msone` history ref entries now optionally record
  `symbolicBranchName` for HEAD; an **explicit null** means detached.
  Old files without this key remain supported with inferred main attachment
  only when the HEAD and main targets match.
- `ProjectSaveCoordinator` now gets actual persistent refs and the pure
  builder exports custom branch and bookmark names rather than reconstructing
  generic alternate IDs.
- `ProjectHistoryReferenceImportPlan` validates all declared target IDs,
  chosen HEAD and any attached branch before importing.
- Project replacement/new-session import persists the exact named refs with
  remapped checkpoint IDs **inside the existing Isar transaction**, rather
  than losing labels to an autogenerated reference catalog.
- Unsupported/corrupt references still abort the entire import. Older
  archives without any historyRefs remain importable.

## Regression coverage

- Named branch/bookmark creation, renaming, deletion constraints, duplicate
  labels, invalid names, missing/foreign targets and lightweight storage.
- Named branch checkout, direct detached checkout, distinct branch tips
  and branch-local subsequent V2 commits.
- Renaming an attached branch preserves symbolic HEAD.
- Export/import of custom names and explicit detached attachment, with new
  Isar target IDs.
- Existing checkpoint integrity and compatibility suites remain active.
